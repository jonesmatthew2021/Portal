How to hand one to Claude

  1. Download the file you want.
  2. Start a new chat at claude.ai and attach it — the paperclip, or drag it into the message box. Give each half its own chat, so one review isn't reading around the other.
  3. Ask your question. One of the prompts below will do to start; there is no need to explain what the portal is, because each file says so at the top.

For everything except the certificates

This is the source of a crew portal for a vessel, with the certificate side
removed and reviewed separately - so please ignore anything missing that is
marked as being in the other file. It tracks the crew roster and 28-day
swings, handover notes, correspondence, documents and suggestions, and it is
used on phones by crew and by shore staff.

Please read it and tell me:

1. Anything actually broken or likely to break - wrong dates in the swing
   and roster logic, cases where two people editing at once lose each
   other's work, uploads that can fail silently, errors that would be
   invisible to whoever hit them.
2. Anywhere the sign-in and the admin permissions do not do what the code
   around them assumes.
3. Anything a crew member on a phone would find confusing or easy to get
   wrong.

Point to the code you mean. Please say which findings you are confident
about and which are guesses, and don't rewrite anything yet.

For the certificates

This is the certificate side of a crew portal for a vessel, lifted out of a
much larger app so it can be checked closely. A spreadsheet of qualification
expiry dates becomes a matrix, one row per person; certificate documents are
uploaded, matched to people by filename, read for the dates inside them, and
those dates are compared against the matrix for an admin to accept or
dismiss.

This is the part where being wrong matters most - an expiry read a month
late could put someone to sea unqualified. Please be hard on it:

1. Every way a date could come out wrong. Parsing, time zones, two-digit
   years, day-versus-month order, dates read from spreadsheet cells,
   rounding when working out days remaining, the boundaries of the colour
   bands.
2. Certificates matched to the wrong person, or a match quietly missed.
3. What happens when a certificate is unreadable, half-read, uploaded
   twice, or when the analysis is interrupted partway through.
4. Anywhere a wrong result would look like a right one to an admin
   accepting it.

Point to the code you mean. Please say which findings you are confident
about and which are guesses, and don't rewrite anything yet.

What has been left out of all of them

The logo and the app icons are embedded in the portal as base64 and account for roughly 190 KB — thousands of characters of gibberish that would crowd out the code and waste most of the reviewer's attention. Each one is replaced by a short note saying what was removed. Generated bookkeeping, meaning package-lock.json and the migration snapshots, is left out too. No code is shortened or reordered.

Uploaded files — certificates, spreadsheets, documents — are held by Netlify rather than in the source, so a review sees the code that handles them but not the files themselves. If you want a particular certificate or spreadsheet checked, download it from the portal and attach it alongside.

Keep them internal

The management team signs in by picking a name, and the shared ADMIN account's password sits in the portal's source and is therefore in these files. That is already true of the live page — anyone who can open the portal can read it — but it does mean the downloads should be treated as internal, and this page is kept out of search engines.

Getting fresh copies

The files are packaged from the source rather than written by hand, so they are regenerated by running node scripts/build-review-bundle.mjs and redeploying. The split is by declaration, not by line number, so it survives the code moving around. If the portal has been changed since these copies were packaged, the notice at the top of this page will say so.
